# 0.8.1 预览延迟热修

## 问题与定位

0.8.0 在已保存作品中开启大范围 Bloom、外发光和水平模糊后，移动底图、标题和修改文字都会重新计算相同的光效。光效输出画布设置 `willReadFrequently: true`，将多次大半径模糊强制放到软件光栅化路径，即使系统 GPU 正常也会出现秒级延迟。重启后会恢复同一作品及光效参数，因此延迟持续存在。

排查前使用 SQLite 在线备份保存作品数据库，并复制对应素材、字体、谱面和作业目录。原作品目录不用于自动化编辑或性能测试；备份、素材和运行日志保留在本机忽略目录，不纳入源码及分发包。

## 修复

- 仅在读取像素的画布使用读优化；光效输出和色彩绘制画布允许 GPU 加速，光效算法、半径、分辨率和绘制顺序保持原样。
- 缓存不可变的完整分辨率光效栅格，以字形、字体、字号、颜色、源图、实际尺寸和完整光效参数作为依赖；位置与对象旋转只改变合成。3D 光效使用实际 3D 栅格身份，手绘融合草稿不复用可变像素。
- 缓存合并相同的进行中计算，失败后可重试；按最近使用顺序回收，像素预算 96 MiB、最多 32 项，不累积无限历史帧。
- 输入变化后先给界面一次绘制机会，再启动较重的合成；合成直接返回完成的画布，减少一次中间画布分配和复制。显示画布只在尺寸改变时重设宽高，其他更新清除旧像素并绘制，保持透明区域正确。
- 保留自动保存、撤销重做、旧作品兼容、3D、滤镜、蒙版及导出行为。独立构建 0.8.1，不覆盖 0.8.0 成品。

## 性能基线与结果

同一电脑、同一作品副本、同一原生 Qt WebEngine、1440×1080 输出，使用相同脚本分别运行旧 EXE 与修复版本。显卡为 Intel UHD / ANGLE D3D11。

| 操作 | 0.8.0 初始采样 | 初轮源码候选 | 0.8.1 最终 EXE |
| --- | --- | --- | --- |
| 移动底图 | 1607–1627 ms | 10–13 ms | 33–36 ms |
| 移动标题 | 1651–1667 ms | 9–15 ms | 30–43 ms |
| 改发光强度 | 1630–1635 ms | 75–98 ms | 151–194 ms |
| 输入标题 | 1923–2538 ms | 98–133 ms | 211–311 ms |

以上为本机同一作品副本的实测，旧版为初始原生窗口采样，最终版在可见窗口中采样；并非跨硬件或任意复杂作品的速度承诺。最终版优先给输入界面绘制机会，相应预览包含等待显示帧的时间。证据保存在本机 `artifacts/hotfix-081/`。

对同一作品的旧、新 1440×1080 原生画布做质量对照：RGBA 通道平均差 0.119／255、99 分位差 2／255、最大差 5／255，86.0% 像素完全相同。微小差异来自 GPU／CPU 光栅化，未减少图像尺寸、光效半径或采样分辨率；不宣称新旧引擎输出逐位相同。

## 验证

新增缓存单测 3 项，覆盖进行中计算复用、内存回收、超预算项、失败重试与被回收任务的晚到结果。新增同一真实原生引擎性能用例用于源码和冻结成品：移动预览小于 250 ms，文字／调光小于 500 ms，UI 首帧与计时器响应均小于 120 ms；移动时不重复提交未改动光效；导出和刷新后的完整分辨率像素必须与最终预览完全一致。

旧 0.8.0 在新增成品用例中以移动预览 1895 ms 真实失败。修复后源码和正式 EXE 用例均通过，成品专项耗时 24.77 秒；前端类型检查、lint、48 项单测和构建通过。正式成品 CRC、SHA-256、资源集合、前端构建、使用说明与发布清单一致性校验通过，私人素材未打入包。全量回归结果在交付前补充。

## 全量回归中的首帧计时诊断

第一轮完整执行结果为 464 通过、1 失败、0 跳过，用时 1273.97 秒。失败来自正式 EXE 性能用例的 UI 首帧 144.8 ms，超过原有 120 ms 门槛；其余功能回归通过。该轮 XML、完整日志及检查结果保存在本机 `artifacts/hotfix-081/failed-full-run-01/`，不覆盖或删除失败证据。额外 15 项原谱面测试已通过。

进一步诊断同时记录画布提交、16 ms 计时器和主线程长任务：可复现到画布 18.8 ms、计时器 20.7 ms、没有长任务，而隐藏原生窗口的 RAF 回调为 150.8 ms。仅使用焦点仿真或关闭 Chromium 遮挡节流仍有偶发 456–472 ms 的 RAF 延后，因此不能将这些隐藏窗口采样当作真实可见首帧，也不能据偶尔通过宣告稳定。相同测量环境下，旧 0.8.0 仍以 4343.7 ms 画布延迟失败。

该阶段准备改用短暂可见的临时原生窗口检验首帧，保留全部原性能门槛，并增加独立计时器响应门槛。窗口只操作隔离的临时作品，不修改真实作品，也不发送物理键鼠输入。用户批准后，以 `tools/test-all.ps1 -VisiblePerformanceTests` 运行完整测试；未授权时性能用例明确失败，不跳过或默认当作通过。该阶段的失败结果保留供复核。

焦点仿真的含义可查 [Chrome 官方说明](https://developer.chrome.com/docs/devtools/rendering/apply-effects#emulate-a-focused-page)；原生窗口节流结论依据本机计时对照，不能仅用文档替代实测。

用户随后批准可见窗口测试。可见窗口仍复现首帧 140.9 ms、画布 20.5 ms 的延后，说明此前仅归因为隐藏窗口的判断不完整。进一步修复输入与重绘的时序竞争及重复画布重建：源码可见性能、原连续滑块、光效、滤镜和融合共 14 项专项通过，48 项前端单测、类型检查、lint 与构建通过。连续滑块测试改为统计实际画布绘制次数，原 36 次事件、1400 ms 总耗时、120 ms 定时器延迟与至少 2 个中间帧的断言全部保留。

最终源码和重新构建的 EXE 在真实可见窗口中连续两轮通过，每轮 2 项；全部首帧、计时器、移动／文字／调光延迟及导出与冷渲染像素断言保持原门槛。最终 EXE 的同一作品采样最大预览 310.9 ms、最大 UI 首帧 81.1 ms。重新抓取最终完整分辨率画布，与旧版的质量差异仍为平均 0.119、99 分位 2、最大 5／255。
